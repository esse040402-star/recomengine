## 확인 결과와 범위

2026-11-15 작업 시작 시 main=cb09273. 원격 브랜치는 main만 확인됐습니다.
팀원 작성 모바일 제외 개정 설문은 아직 없습니다. 기존프로젝트/data/survey_questions.json과 첫7문항 모두 모바일 선택지가 남아 있었습니다.
이번 변경은 첫7문항의 게이머/비게이머 원본 7문항에 적용했습니다. 모바일 선택지만 제거하고 남은 선택지 ID를 유지하며 버전은 quick-1.1.0으로 올렸습니다. 팀원의 별도 개정안을 적용했다고 주장하지 않습니다.
기존프로젝트의 온보딩·심층·취향 설문은 별도 시스템입니다. 확정되지 않은 선택지 의미를 임의 변환하지 않았으며 이 파일들에는 이번 계산 규칙을 적용하지 않았습니다. 통합 시 같은 canonical code를 명시적으로 부여해야 합니다.

## 사용

Render의 기존 Build/Start Command를 유지합니다. Root Directory는 빈칸이어야 합니다. 기존 main 자동 배포가 켜져 있으면 업데이트 후 반영됩니다.

- GET `/api/games/1174180`: 원본 응답을 유지하고 `normalized` 필드 추가
- GET `/api/surveys/quick/gamer`: 게이머 7문항 정의
- GET `/api/surveys/quick/nongamer`: 비게이머 7문항 정의
- POST `/api/surveys/quick/recommend`: 답변과 AppID 후보를 제출해 실제 API 기반 비교
- [Swagger 테스트](https://recomengine-game-api.onrender.com/docs)

POST 예:
```json
{"track":"gamer","version":"quick-1.1.0","answers":{"q1":["0"],"q2":["3"],"q3":["2","3"],"q4":["0"],"q5":["2"],"q6":["5"],"q7":["0"]},"appids":[1174180,413150]}
```

이는 지정 후보(요청당 최대 10개) 내 비교입니다. 전체 Steam 목록에 대한 상세정보 수집·전체 추천은 구현하지 않았습니다. 캐시된 게임 응답은 기본 15분 재사용합니다.
`matched_weights`, `match_evidence`로 반영 점수와 원본 출처를 확인합니다. 미확정 조건은 `unsupported_weights`, `warnings`로 확인합니다. 점수는 확률·정확도가 아닌 팀 규칙 합산 점수입니다.

기존 첫7문항 로컬 테스트는 첫7문항 폴더에서 `python -m quick_survey.refresh`로 Render의 통합 정보를 받은 뒤 실행합니다. 후보는 기존 catalog.json 범위입니다. 예전 캐시나 수동 스냅샷은 새 추천에 쓰지 않으며 데이터가 없으면 `data_required`입니다. 사용자 답변·결과 저장은 기존 흐름을 유지합니다. 최종 2차 통합 ZIP은 이번 작업에서 재생성하지 않았습니다.

## 의미 구분

- 동의어는 코드 하나로 통합하고 근거는 출처별로 모두 보존합니다. 두 공급자의 같은 특징을 이중 가산하지 않습니다.
- 서로 다른 문항에서 같은 특징을 선호하면 그 가중치는 누적됩니다.
- 미매핑 키워드는 `unmapped`에 남깁니다. 모든 IGDB 키워드를 억지로 장르로 만들지 않습니다.
- 액션은 genre:action, 오픈월드는 tag:open_world. RPG, 2D, 3D, 시점은 서로 다릅니다.
- 멀티플레이와 PvP, 일반 시뮬레이션과 아늑함, 3D와 사실적 화풍을 동일시하지 않습니다.
- 클리어 시간은 초→시간 변환 후 completion_hours에만 저장합니다. 세션 길이는 알 수 없음입니다.
- 가격은 Steam 한국 상점 반환값의 1/100 단위로 변환하고 통화를 보존합니다. 가격과 사양은 원본 7문항에 예산·구체 PC 사양 질문이 없어 임의 점수화하지 않습니다.
- IGDB 평점과 Steam 긍정 리뷰 수치는 별도로 보존하며 하나의 점수로 합치지 않습니다.
- 모바일 전용은 추천 제외. PC/콘솔 동시 출시작은 PC/콘솔 후보로 유지합니다. UMPC 검증 데이터 없음은 경고합니다.
- 부정 선호는 감점이며 절대 배제 필터가 아닙니다. API에 없는 멀미·과금압박 등은 사실로 추정하지 않습니다.
